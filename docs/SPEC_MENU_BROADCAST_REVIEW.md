# סקירת שינויים לפני שידור לקופות — אפיון ומימוש

## האפיון המקורי (מסמך הלקוח)

- הפיצ'ר פעיל **רק** כשמודול השולחנות פעיל לסניף / לעסק. הזרימה: עריכת תפריט ← השינויים נשמרים כטיוטה ← "שדר לקופות" ← סקירת השינויים ← אישור ← שידור ← גרסה מופצת לקופות.
- מסך הסקירה מציג:
  - מוצרים שנוספו / הוסרו;
  - שינויי מחירים;
  - שינויי קטגוריות;
  - שינויי תוספות;
  - שינויי זמינות;
  - שינויי שעות;
  - שינויי תפריטים;
  - לאילו קופות / סניפים השינוי עומד להישלח.
- כשמודול השולחנות **לא** פעיל: אין שלב סקירה; השידור עובד בדיוק כמו היום (עריכה ← מגיע לקופות, בלי מסך ביניים).
- תנאי מערכת: דגל ברמת סניף / עסק, `TablesEnabled`. ‏`TablesEnabled=true` ← `MenuChangeReviewBeforeBroadcast=true`; ‏`false` ← `false`.
- **חשוב:** זה לא קשור לסוג ההזמנה הנוכחית ("האם פתוחה עכשיו הזמנת שולחן?") אלא לשאלה אם מודול השולחנות פעיל בסניף. סניף שעובד עם שולחנות + Take Away + הזמנה מהירה נחשב סניף שולחנות, ולכן **כל** שינויי התפריט שלו עוברים סקירה — גם שינוי בתפריט ה-Take Away.
- הגדרה מומלצת בניהול הסניף: "סוגי עבודה" ☑ שולחנות ☑ Take Away ☑ הזמנה מהירה ☐ משלוחים; סימון "שולחנות" מפעיל את הסקירה אוטומטית.
- הסיבה: במסעדות עם שולחנות יש הזמנות ארוכות ופתוחות במהלך השירות. שינוי מחיר / מוצר / תוספות / קטגוריה / תפריט פעיל צריך בקרה נוספת לפני שהוא מגיע למכשירי המלצרים ולקופות.

עיקרון מנחה מהמשתמש: **לא לדרוס שום יכולת קיימת — רק להוסיף.** סניף בלי שולחנות עובד בדיוק כמו קודם.

---

## 1. מתי סניף במצב סקירה

`MenuChangeReviewBeforeBroadcast` נגזר אוטומטית (`review_state` ב-`server/app/services/menu_broadcast.py`):

- **TablesEnabled** = פרמטר הקופה `tablesMode` שונה מ«כבוי» באחת מהקופות הפעילות של הסניף. כל קופה נפתרת דרך השכבות הרגילות (קופה ← נקודת מכירה ← סניף ← חברה ← ברירת מחדל). סניף בלי קופות עדיין — לפי ערך הסניף עצמו.
  - לכן סניף שעובד גם עם שולחנות וגם ב-Take Away — סניף שולחנות. זה לא תלוי בהזמנה שנמצאת עכשיו בקופה.
  - קופה בודדת שהוגדרה «כבוי» לא מכבה את הסניף, אם קופה אחרת בו עם שולחנות.
- **עקיפה, בלי לשנות את ברירת המחדל:** פרמטר קופה מובנה חדש, `menuBroadcastReview` ("סקירת שינויים לפני שידור לקופות"):
  - «אוטומטי (לפי שולחנות)» — ברירת המחדל: לפי TablesEnabled.
  - «תמיד» — סקירה גם בלי שולחנות.
  - «אף פעם» — בלי סקירה גם עם שולחנות.
  - נקבע לסניף או לחברה (סניף גובר על חברה). ערכים ברמת נקודת מכירה / קופה לא נחשבים, כי הסקירה היא של הסניף כולו. הקופה עצמה מתעלמת מהפרמטר.

## 2. מה הקופות מקבלות — גרסאות שידור

### טבלה חדשה: `catalog_publications`

עמודות: tenant, shop, ‏version (1, 2, 3… לכל סניף), ‏kind ‏(`initial` / `broadcast`), ‏snapshot ‏(JSON), ‏summary ‏(ספירה לכל סעיף), ‏fingerprint, ‏published_at, ‏published_by, ‏note, ‏closed_at.

### ה-snapshot — רמת סניף

ה-snapshot הוא בדיוק מה שקופות הסניף היו מקבלות מ-`GET /sync/{m}/catalog` ברגע השידור, ברמת הסניף. הוא נבנה עם אותן פונקציות שה-sync משתמש בהן (`_serialize_merged_product`, `_categories_for_shop`, `_serialize_category`, `menu_block`):

- `products` — כל מוצר גלובלי ששויך לסניף: המחיר של הסניף, הרישום (`shopListed`), וכל מה שהמוצר "הוא".
- `productGates` — קלטי הזמינות שעוברים סקירה: הדגל של המוצר עצמו וערך החברה. יש גם ערך הסניף, אבל רק בשביל מוצר שהסניף כבר לא משויך אליו.
- `categories` — הקטגוריות שהסניף רואה, עם השם של הסניף עבורן. ‏`referencedCategories` — קטגוריות נוספות שמוצר מפנה אליהן (כמו ה-merge של delta). ‏`categoryGates` — ה-is_active של הארגון.
- `menu` — בלוק התפריט כולו: קבוצות תוספות ואפשרויות, קישורים, הערות הכנה, ארוחות, הגדלות מכירה ושעותיהן, מנות (courses) ומגבלות.

**למה רמת סניף ולא snapshot לכל קופה:** מה שייחודי לקופה מוסף מעל ה-snapshot **חי** בכל משיכה: נקודת המכירה, העותק המקומי, הרשימה של הקופה, והנעילות שלה. כך:

- נעילה מהקופה לא מחכה לשידור;
- קופה שעוברת נקודת מכירה מקבלת את מה שמתאים לה;
- קופה חדשה בסניף מקבלת את הגרסה בלי snapshot משלה.

זה גם הפתרון הפשוט ביותר: snapshot אחד לסניף, ושכבת-על אחת (`serve`) שמחקה בדיוק את `_products_merged_for_shop_machine`. בטסט, ובהרצה על הנתונים האמיתיים, הפלט זהה לפלט החי שדה-בשדה, כולל `updatedAt`.

### מה עובר סקירה ומה נשאר מיידי

| עובר סקירה (מהגרסה המשודרת) | מיידי (חי, כמו היום) |
|---|---|
| מוצר: שם, תיאור, מחיר (כולל מחיר סניף), שיוך / הסרה מהסניף (`shopListed`), קטגוריה, מק"ט, ברקוד, מע"מ, שובר, בון, מחיר פתוח, שקיל, יחידה, "לא מקבל הנחות", אלרגנים, מנה (course), מגבלות הזמנה ומילוי חוזר | זמינות ברמת סניף, נקודת מכירה וקופה. אלה השורות שכפתור "אזל" / נעילה מהקופה כותב, וגם מתגי הדשבורד לאותן רמות. זו "נעילת פריט" תפעולית |
| זמינות שנקבעה בדשבורד ברמת המוצר עצמו (`is_available`) או ברמת החברה | קטגוריה שכובתה לסניף / לנקודת מכירה / לקופה (מהקופה או מהדשבורד) |
| קטגוריה: שם (כולל שם הסניף), אב, סדר, צבע, תמונה, מנה, בון, הפעלה / כיבוי ברמת הארגון; קטגוריות שנוספו / הוסרו | מלאי: `inStock` (הדגל של המוצר / העותק המקומי) וכמות |
| בלוק התפריט כולו: קבוצות תוספות ואפשרויות (שם, מחיר, ברירת מחדל…), קישורי תוספות לקטגוריה / מוצר, הערות הכנה, ארוחות, הגדלות מכירה (כולל שעות וימים), מנות | תמונת המוצר, כולל תמונה שצולמה בקופה |
| | הרשימה של הקופה (`inMachineCatalog`) ומצב הקטלוג שלה |
| | מוצרים מקומיים של הקופה (POS-only) |
| | לקוחות ושוברים |
| | כל מה שמחוץ ל-payload הזה: סדר כפתורים וסדר קטגוריות מהקופה (שכבת ההגדרות), הגדרות, פרמטרים, מבצעים, מדפסות, שולחנות |

הערות:

- **עריכה ממצב העריכה של הקופה** (מוצר חדש, מחיר, שם) היא שינוי תוכן. בסניף במצב סקירה היא טיוטה כמו עריכה בדשבורד: מופיעה בסקירה, ומגיעה לקופות (גם לקופה שבה נערכה) רק אחרי שידור.
- **אין שעות פעילות** למוצרים, לקטגוריות או לתפריטים בקטלוג. "שינויי שעות" הם חלונות הזמן והימים של הגדלות המכירה. המבצעים הם מודול נפרד, לא בתפריט.

### משיכת הקטלוג (`GET /sync/{m}/catalog`)

הקופה לא משתנה: אותו endpoint ואותו פורמט.

- **סניף לא במצב סקירה** — בדיוק כמו קודם.
  - יש שאילתה אחת נוספת לגרסה האחרונה, ושלוש לפרמטרים.
- **סניף במצב סקירה:**
  - משיכה מלאה (`since` ריק) ← כל הגרסה המשודרת.
  - משיכת delta שה-`since` שלה לפני הגרסה (עם מרווח של 2 דקות, `RESEND_WINDOW`, למשיכה שהתנגשה עם השידור):
    - כל הגרסה, כולל בלוק התפריט;
    - **ועוד** כל מוצר וקטגוריה שהיו בגרסה שהקופה החזיקה וירדו בגרסה הזו, שנשלחים נעולים: מוצר `isAvailable=false`, `inStock=false`, `shopListed=false` (כמו מוצר שהוסר מהסניף היום); קטגוריה `isActive=false`. המשיכה המלאה הבאה של הקופה מורידה אותם מהרשימה, כמו היום.
  - delta אחרי הגרסה ← רק שורות שהקלטים החיים שלהן זזו (נעילות, מלאי, רשימה, נקודת מכירה…). בלוק התפריט לא נשלח ("השאר מה שיש").
- **גרסה ראשונה אוטומטית:** סניף במצב סקירה בלי גרסה פתוחה מקבל גרסה `initial`, שהיא הקטלוג החי כפי שהוא, במשיכה הראשונה של אחת הקופות או כשנכנסים לסקירה בדשבורד. אם עוברים לסקירה דרך כרטיס "סוגי עבודה", הגרסה נוצרת מיד. כך ברגע המעבר שום דבר לא משתנה בקופות.
- **יציאה ממצב סקירה:**
  - הגרסה האחרונה נסגרת (`closed_at`) במשיכה הראשונה מחוץ למצב סקירה.
  - קופה שמשכה לפני הסגירה (עם מרווח 2 הדקות) מקבלת את הקטלוג החי **במלואו** פעם אחת, כך שגם טיוטות ישנות מגיעות אליה.
- **חזרה למצב סקירה** אחרי יציאה ← גרסה `initial` חדשה מהקטלוג החי.
- **ניקוי:** ה-snapshot נשמר ל-20 הגרסאות האחרונות של כל סניף. בגרסאות ישנות יותר נשאר רק הסיכום, לרשימת "גרסאות שידור".

## 3. הסקירה (diff)

ההשוואה היא בין הטיוטה (הקטלוג החי ברמת הסניף) לבין הגרסה האחרונה (`diff`). שדות תפעוליים לא נבדקים. סעיפים:

| סעיף | מה נכלל |
|---|---|
| `products` | נוסף / הוסר (כולל שיוך או הסרה של "מופיע בסניף"); שונה — כל שדה תוכן, וקטגוריה מוצגת בשם |
| `prices` | מחיר לפני ← אחרי (המחיר האפקטיבי של הסניף, כולל מחיר סניף) |
| `categories` | נוספה / הוסרה / שונתה: שם, אב, סדר, פעילה, צבע, תמונה, מנה, בון |
| `modifiers` | קבוצות (נוספה / הוסרה / שונתה, וכל אפשרות: נוספה / הוסרה / מחיר / שם / ברירת מחדל…); קישורי תוספות לקטגוריה / מוצר של הסניף; הערות הכנה (לכל המנות, לקטגוריה, למוצר); ארוחות |
| `availability` | זמינות שנקבעה בדשבורד ברמת המוצר / החברה |
| `hours` | שעות וימים של הגדלות מכירה |
| `menu` | מנות (courses) ושאר שינויי הגדלות המכירה (נוספה / הוסרה / שונתה) |

בנוסף: **לאן זה נשלח** — הקופות הפעילות של הסניף, עם מספר, נקודת מכירה, ומצב מחובר / לא מחובר.

שינוי בבלוק התפריט שנוגע רק למוצרים או לקטגוריות שהסניף לא מוכר לא נספר בסניף הזה. השידור עדיין כולל אותו.

## 4. Endpoints (`server/app/routers/menu_broadcast.py`)

| Endpoint | מה |
|---|---|
| `GET /menu-broadcast/status?companyId=&shopId=` | הסניפים במצב סקירה בטווח, וכמה שינויים כל אחד לא שידר (לבאנר) |
| `GET /shops/{id}/menu-broadcast/preview` | הסקירה: מצב ולמה, הגרסה שבקופות, השינויים לפי סעיף, הקופות, `fingerprint` |
| `POST /shops/{id}/menu-broadcast` | "אישור ושידור" `{fingerprint?, note?}` ← גרסה חדשה + התראה לקופות (`reason=menu_broadcast`) |
| `GET /shops/{id}/menu-broadcast/history` | "גרסאות שידור" |
| `GET /companies/{id}/menu-broadcast/preview` | הסקירה של כל סניפי החברה (וחברות הבנות) שבמצב סקירה |
| `POST /companies/{id}/menu-broadcast` | `{shops:[{shopId, fingerprint}], note?}` — כל סניף כגרסה נפרדת |
| `GET / PUT /shops/{id}/work-types` | כרטיס "סוגי עבודה" |

סירובים (409):

- `menu_review_off` — הסניף לא במצב סקירה.
- `menu_nothing_to_broadcast` — הטיוטה זהה לגרסה.
- `{code: menu_changed_since_preview}` — הטיוטה זזה אחרי הסקירה שאושרה. נעילה / מלאי / תמונה **לא** מזיזות את הטיוטה.
- `menu_broadcast_conflict` — שני שידורים באותו רגע.

הרשאות:

- **קריאה:** מי שאחראי על הסניף — סופר אדמין, מפיץ, מנהל החברה, מנהל הסניף.
- **שידור:** מי שעורך קטלוג (מנהל סניף ומעלה).
- **סוגי עבודה:** סופר אדמין בלבד, כמו הפרמטר `tablesMode` עצמו.

## 5. "סוגי עבודה" (כרטיס בדף הסניף)

- ☑ **שולחנות** — משקף ושולט ב-`tablesMode` של הסניף:
  - ביטול הסימון ← «כבוי» לסניף, ומחיקת ערכי `tablesMode` ברמת נקודות המכירה והקופות של הסניף (אחרת השולחנות היו נשארים פעילים בהן).
  - סימון כשהסניף כבוי ← שואל איזה מצב, ברירת מחדל «קופה אחת».
- ☐ **Take Away**, ☐ **הזמנה מהירה**, ☐ **משלוחים** — נשמרים בטבלה חדשה `shop_work_types`, **לידיעה בלבד**: שום דבר לא קורא אותם, והם לא מסתירים או משנים שום דבר קיים.
- מתחת לתיבות:
  - "סקירת שינויים לפני שידור: פעילה / כבויה" ולמה (שולחנות פעילים בקופות X / «תמיד» / «אף פעם» / אין שולחנות);
  - בחירת העקיפה (`menuBroadcastReview` לסניף);
  - קישור לסקירה.

## 6. דשבורד

- **באנר** בעמודי הקטלוג: מוצרים, קטגוריות, תוספות, הגדלות מכירה, מיון סניף, אשף מוצר.
  - כשיש בטווח סניף במצב סקירה עם שינויים: "יש שינויים שטרם שודרו לקופות (N)" + "שדר לקופות".
  - כשאין שינויים: שורה שקטה שמזכירה שהשינויים יחכו לשידור, וקישור ל"גרסאות שידור".
  - סניפים בלי סקירה: **אין שום דבר** — הכול כמו היום.
- **מסך הסקירה** `/dashboard/products/broadcast`, לפי ה-scope:
  - **סניף:** סעיפים עם ספירות, לפני ← אחרי, הקופות שיקבלו, הערה, "אישור ושידור", ומתחת "גרסאות שידור" (גרסה, מי, מתי, סיכום).
  - **חברה:** כל סניף במצב סקירה, עם אישור לכל סניף ו"אישור ושידור לכל הסניפים".
  - **ארגון:** רשימת הסניפים במצב סקירה, לבחירה.
- לא נוסף פריט לתפריט הצד, כדי שארגון בלי שולחנות לא יראה שום שינוי. העמוד נפתח מהבאנר ומכרטיס "סוגי עבודה", ומודגש תחת "מוצרים".

גרסה 1.0 · 07.10.2026 · ענף `feat/r2m-pos-2026-10`

> משלים את `docs/SPEC_DEVICE_ROLE_MODEL.md` (סוג מכשיר, פלטפורמה, מכשירים לא-קופתיים), `docs/SPEC_KIOSK.md` (הקיוסק),

## 1. הבקשה ותשובה קצרה

הבעלים: "את ההתקנה שעשית ב-WEB יכולה להתאים גם לקופת ווינדוס, אז תהפוך אותה למודולרית. תחשוב על עדכונים איך זה קורה, כי עכשיו
צריך גם ווינדוס וגם אנדרואיד. האם עדכונים יורדים אוטומטית?" ובהמשך: "ההתקנה של הווינדוס יכולה לכלול KDS, קופה, קיוסק, מסך
מוכן/לא מוכן, וההגדרה מה הוא יהיה בהוספת מכשיר בענן במהלך הצימוד. חשוב מאוד: מכשירים KDS ומסך מוכן/לא מוכן אינם מערכות קופה
וחשבונאיות."

**האם עדכונים יורדים אוטומטית? כן — בשתי הפלטפורמות ההורדה תמיד אוטומטית וברקע; ההתקנה אוטומטית לפי השיוך:**

| | הורדה | התקנה |
|---|---|---|
| **אנדרואיד** | בכל סנכרון (`CloudSync` ← `AppUpdateRepository.check`), ברקע, עם בדיקת SHA-256 | שיוך "התקנה אוטומטית": כשהקופה סגורה (אין משמרת), או במשמרת פתוחה כשהקופה שקטה 2 דק׳ (אין סל, תשלום או שולחן). אחרת מהתפריט. **שקטה** באנדרואיד 12+ ובכל מכשיר שהאפליקציה בו device owner; **דורשת לחיצה** באנדרואיד 10/11 (ה-F20) — §5 |
| **Windows** | בהפעלה (אחרי דקה), כל 15 דק׳ ו"בדוק עכשיו", ברקע, עם בדיקת SHA-256 וגודל | שיוך "התקנה אוטומטית": כשהמכשיר פנוי (קיוסק במסך פתיחה / סגור, בלי הזמנה ובלי תשלום), ואם הוגדר חלון — רק בתוכו (למשל 02:00–05:00). תמיד שקטה (`/S`), והאפליקציה עולה מחדש לבד. "התקן עכשיו" בטכנאי — בכל זמן חוץ מבזמן הזמנה/תשלום |

בלי "התקנה אוטומטית" בשיוך — הגרסה יורדת ומחכה ל"התקן עכשיו" (טכנאי ב-Windows, תפריט בקופה).

## 2. מסך אחד בדשבורד — "עדכוני גרסה"

`/dashboard/app-updates` (סופר-אדמין; טבלת הפריסה גם למנהלי מכונות של הארגון):

- **מתג פלטפורמה** (הכל / אנדרואיד / Windows) מעל הכול.
- **גרסאות:** העלאה — בוחרים פלטפורמה; אנדרואיד: APK (הגרסה נקראת מה-manifest); Windows: `R2M-POS-Windows-<גרסה>-setup.exe`
  (הגרסה משם הקובץ או מוקלדת; versionCode מחושב `a·1,000,000 + b·1,000 + c`). הערות. הענן מחשב SHA-256 וגודל. הוצאה משימוש (`isActive`).
- **שליחה (שיוך):** גרסה → ארגון / חברה / סניף / נקודת מכירה / מכשיר אחד, "התקנה אוטומטית", **אחוז פריסה** (פריסה מדורגת), ול-Windows
  גם **"אפשר חזרה לגרסה קודמת"** ו**חלון התקנה**.
- **שיוכים פעילים:** פלטפורמה, אחוז (ניתן לשינוי במקום), חלון, ביטול.
- **פריסה:** כל מכשיר — פלטפורמה, תפקיד (קופה / קיוסק / מסך מטבח / מסך מוכן), הגרסה שהוא מריץ (מה-heartbeat), גרסת היעד ומאיזו
  רמה, הסטטוס האחרון שדיווח (מוריד / הורד / מתקין / הותקן / נכשל + סיבה / נדחה), **מי מפגר** (מסנן "רק מכשירים שמפגרים" וספירה לכל פלטפורמה).

## 3. בענן — גרסאות, שיוכים, פריסה מדורגת, חזרה לגרסה

- `app_releases.platform` = `android` | `windows` (ברירת מחדל `android` — כל מה שהיה). שם גרסה ייחודי **בתוך פלטפורמה**.
- **שיוך וקדימות — אותם כללים, לכל פלטפורמה בנפרד:** מכשיר → נקודת מכירה → סניף → חברה → ארגון; ברמה אחת — החדש. שיוך למכשיר
  גובר על שיוך לסניף. שיוכי אנדרואיד ו-Windows לא משפיעים זה על זה (קיוסק Windows וקופת אנדרואיד באותו סניף מקבלים כל אחד את שלו).
  פלטפורמת המכשיר: הפרמטר `platform` בבקשה (בלי — `android`, כמו הקופה היום); בדשבורד ובהורדה — `device_info.platform` מהצימוד.
- **פריסה מדורגת:** לשיוך יש אחוז (1–100). מכשיר בשלב אם `sha256("<assignment>:<machine>") mod 100 < אחוז` — קבוע, ולכן הגדלת האחוז
  משאירה את מי שכבר בפנים. מכשיר מחוץ לשלב מדלג על השיוך וממשיך בסדר הרגיל — כך שיוך ישן באותה רמה ממשיך להחזיק את שאר הסניף בגרסה הקודמת.
- **חזרה לגרסה קודמת (rollback):** Windows — שיוך של גרסה ישנה עם "אפשר חזרה" (`allowDowngrade`): המכשיר מקבל versionCode נמוך יותר
  (לעולם לא את אותה גרסה), והמתקין של NSIS מתקין אותה מעל. **אנדרואיד — לא אפשרי:** אנדרואיד לא מתקין versionCode נמוך בלי הסרה
  (= מחיקת המסד המקומי, מסמכים ומונים). "חזרה" באנדרואיד = לבנות את הקוד הישן מחדש עם versionCode גבוה יותר (ה-versionCode הוא מספר
  ה-commits) ולשלוח אותו כגרסה חדשה. הענן מסרב ל-`allowDowngrade` על גרסת אנדרואיד. הוצאה משימוש של גרסה פגומה מחזירה את המכשירים
  לשיוך הבא שחל עליהם, אבל לא מורידה אותם — לשם כך צריך rollback.
- **הורדה:** רק הגרסה שהמכשיר מקבל עכשיו (`404` לכל אחרת), בטוקן של המכשיר.

| נקודת קצה | |
|---|---|
| `POST /app-releases` | multipart: `file`, `platform` (`android`/`windows`), `versionName`, `versionCode` (אנדרואיד, אם לא נקרא), `notes` |
| `GET /app-releases?platform=` | הגרסאות, + `platform` |
| `POST /app-releases/{id}/assignments` | `level`, `targetId`, `autoInstall`, `rolloutPercent`, `allowDowngrade` (Windows), חלון התקנה (Windows) |
| `PATCH /app-release-assignments/{id}` | שינוי אחוז / התקנה אוטומטית / חלון |
| `GET /app-releases/rollout?platform=` | שורה לכל מכשיר: `platform`, `deviceRole`, `currentVersion`, `targetVersion`, `status`, `behind`, `newestVersion` |
| `GET /sync/{m}/app-update?versionCode=&versionName=[&platform=windows]` | ההצעה: כל המפתחות תמיד, + `platform`, `allowDowngrade`, `rolloutPercent`, `installWindow` |
| `GET /sync/{m}/app-update/{id}/apk` (וגם `/file`) | הקובץ — APK או מתקין Windows |
| `POST /sync/{m}/app-update/status` | `downloading` / `downloaded` / `installing` / `installed` / `failed` / `declined` + `message` |

## 4. Windows — "R2M POS ל-Windows", אפליקציה מודולרית אחת

### 4.1 מבנה

מעטפת אחת (`kiosk-desktop/src/main/index.ts`), שכבת שירות משותפת אחת, ומודולים לפי תפקיד:

| שכבה | מה | קבצים |
|---|---|---|
| מעטפת | חלון מסך מלא, `kiosk://`, IPC, זהות ההתקנה | `src/main/index.ts`, `src/main/shell/identity.ts`, `src/preload` |
| שירות משותף | צימוד, הרשאה (טוקן מכונה מוצפן DPAPI), סנכרון, מטמון מדיה, הדפסה (SNBC / ESC-POS RAW ל-spooler או TCP 9100), ספקי תשלום (Nayax LAN, SynqPay), יומנים, טכנאי | `src/main/service.ts`, `sync/`, `media/`, `printer/`, `payment/`, `db/` |
| עדכונים | בדיקה, הורדה, אימות, התקנה, דיווח | `src/main/update/updater.ts`, `src/core/updatePolicy.ts` |
| תפקיד | איזה תפקיד, איזה מודול רץ | `src/core/roles.ts`, `src/main/roles/manager.ts` |
| קיוסק | הקיוסק של היום — ללא שינוי בהתנהגות | השירות + `src/renderer/kiosk` |
| מסך מטבח (KDS) | הלוח והפעולות של מכשיר KDS (תחנה / אקספו / מנהל) | `src/main/roles/kds.ts`, `src/core/kdsBoard.ts`, `src/renderer/roles/kds` |
| מסך מוכן / לא מוכן | מספרי איסוף בהכנה / מוכנים, צליל והבהוב, עובד מהמידע האחרון בלי אינטרנט | `src/main/roles/board.ts`, `src/core/pickupBoard.ts`, `src/renderer/roles/board` |
| קופה, מסך לקוח | פיגום בלבד: גבול מודול, ניתוב, מסך "תפקיד זה יגיע בגרסה הבאה" | `src/renderer/roles/RolePlaceholder.tsx` |

### 4.2 איך נבחר התפקיד — רק בענן

1. בדשבורד, "הוספת מכשיר": סוג מכשיר (קופה / קיוסק / מסך מטבח / מסך מוכן-לא מוכן) + פלטפורמה (Android / Windows) + סניף.
2. במחשב: כתובת שרת + קוד. **אין בחירת תפקיד במחשב**; מסך הטכנאי מציג את התפקיד לקריאה בלבד.
3. אחרי הצימוד: `machines/me` → `deviceRole`. קיוסק פעיל (`kiosk/sync` → `kiosk: true`) תמיד קיוסק. מכשיר שהוגדר מעמוד מסכי המטבח
   (`kds/device`; `pickup` = מסך מוכן) — כמו בקופה, השאלה נשאלת רק למסך או לקופה עם הפרמטר `kdsScreen`.
4. מסך מטבח ומסך מוכן **אינם קופה**: לא פותחים משמרת, לא מוציאים מסמך, לא Z, לא תשלום; ה-heartbeat שלהם בלי עובדות Z. גם הענן אוכף
   (`403 device_not_fiscal`) — `docs/SPEC_DEVICE_ROLE_MODEL.md`.

### 4.3 זהות ההתקנה (החלטות)

- `appId` = `il.co.runnersys.kiosk` — **נשאר**. NSIS מזהה את ההתקנה לפיו; appId חדש היה מתקין אפליקציה שנייה ליד כל קיוסק במקום לעדכן.
- `productName` = `R2M Kiosk` — **נשאר** (שם ה-exe ותיקיית ההתקנה). תיקיית הנתונים `%APPDATA%\R2M Kiosk` **נעוצה בקוד**
  (`app.setPath('userData')`) — בה הטוקן, המונים, המשמרות וה-Zים — ולכן שינוי שם מוצר בעתיד בטוח.
- מה שרואים: כותרת החלון, מסך הצימוד, הקיצור ("R2M POS") וקובץ ההתקנה `R2M-POS-Windows-<גרסה>-setup.exe`.
- **התקנה למשתמש (per-user)** מ-0.2.0: בלי הרשאות מנהל, ולכן עדכון שקט אמיתי תחת משתמש הקיוסק. מתקינים כשמחוברים כמשתמש הקיוסק.
- **מעבר מ-0.1.0** (הותקנה למחשב, עדכון ידני בלבד): משייכים 0.2.0, ובמסך הטכנאי של 0.1.0 לוחצים "התקן עכשיו" פעם אחת. 0.2.0
  נכנסת להתקנה למשתמש עם אותה תיקיית נתונים; את ההתקנה הישנה מסירים פעם אחת (מנהל) — הנתונים נשארים.

### 4.4 זרימת העדכון

1. **בדיקה** — בהפעלה (אחרי דקה), כל 15 דק׳ (`updateCheckMinutes` ב-`%APPDATA%\R2M Kiosk\kiosk.json`), "בדוק עכשיו". רק הצעה
   `platform: "windows"`, עם מזהה ו-SHA-256, לא הגרסה שרצה, ולא נמוכה יותר אלא אם rollback.
2. **הורדה ברקע** ל-`%APPDATA%\R2M Kiosk\updates\<release>.exe.part`, עם גיבוב בזמן ההורדה; גודל + SHA-256 + כותרת `MZ` — או שהקובץ נמחק
   ו-`failed` מדווח. כישלונות חוזרים: המתנה של 1, 2, 4… דק׳ (עד שעה). גרסה מוכנה נשמרת גם אחרי הפעלה מחדש.
3. **התקנה** — רק לשיוך "התקנה אוטומטית", כשמותר:
   - **לעולם לא** בזמן הזמנה או תשלום: לא במסכי הזמנה/תשלום/הצלחה, לא עם בקשה במסופון, לא עם תשלום שממתין לבירור;
   - קיוסק — אחרי דקה בלי שינוי במסך; מסך מטבח — 3 דק׳ בלי נגיעה; מסך מוכן — מיד;
   - אם בשיוך (או ב-`updateWindow` של kiosk.json) יש חלון — רק בתוכו (חלון יכול לחצות חצות).
   - "התקן עכשיו" (טכנאי) — בלי חלון ובלי המתנה, **אבל לא בזמן תשלום** (נבדק גם בשירות וגם במעדכן).
   לפני ההרצה הקובץ מגובב שוב; `installing` מדווח; NSIS רץ `/S --force-run` (שקט, מחליף, מפעיל מחדש) והאפליקציה נסגרת.
4. **אחרי ההפעלה** — הגרסה שרצה מושווית לזו שהותקנה: `installed`, או `failed` עם "ההתקנה לא הושלמה: רצה X במקום Y" (אחרי 15 דק׳).
5. **מסך הטכנאי** (קיוסק: שש נגיעות בפינה + קוד; מסך מטבח / מסך מוכן / פיגום — אותה מחווה): גרסה, מצב (מוריד X%, מוכן להתקנה,
   ממתין לחלון 02:00–05:00, נכשל + סיבה), מדיניות ההתקנה, "בדוק עכשיו" / "התקן עכשיו".

### 4.5 בלי חתימת קוד (עדיין) — SmartScreen

- **התקנה ראשונה** מקובץ שהורד בדפדפן: SmartScreen מציג "Windows protected your PC" ← "More info" ← "Run anyway" (הקובץ מסומן
  mark-of-the-web ואין לו מוניטין של מפרסם חתום).
- **עדכונים אוטומטיים לא עוברים ב-SmartScreen**: האפליקציה מורידה בעצמה (לא דפדפן), אין mark-of-the-web. מה שמגן: HTTPS, טוקן המכונה,
  הורדה רק של הגרסה המשויכת, ו-SHA-256 שהענן חישב בהעלאה (נבדק פעמיים). Defender עדיין סורק.
- **Smart App Control** (Windows 11, התקנה נקייה) חוסם תוכנה לא חתומה בכלל — לכבות במכשירים עד שתהיה חתימה.
- **להמשך:** תעודת חתימת קוד (OV/EV, או Azure Trusted Signing) — electron-builder חותם בבנייה (`win.signtoolOptions` /
  `win.azureSignOptions`); אז אפשר גם לבדוק במעדכן שהמתקין חתום באותו מפרסם לפני ההרצה.

### 4.6 העלאה מסקריפט

```bash
cd kiosk-desktop && npm run dist
R2M_ADMIN_TOKEN=<טוקן סופר-אדמין> npm run publish:release -- --server https://api.example.com --notes "מה חדש" \
    [--assign shop:<uuid> --auto-install --percent 20 --window 02:00-05:00]
```

הטוקן: בדשבורד, DevTools ← `await window.Clerk.session.getToken()` (חי כדקה). הסקריפט משווה את ה-SHA-256 שהענן חישב לקובץ המקומי.

## 5. אנדרואיד — מתי עדכון שקט ומתי צריך לחיצה

| מכשיר | נתיב ההתקנה | לחיצה? |
|---|---|---|
| **device owner** (כל גרסת אנדרואיד) | PackageInstaller session | **לא** — התקנה של ה-device owner לא מבקשת אישור ולא דורשת "התקנת אפליקציות לא מוכרות" |
| אנדרואיד 12+ (הטאבלט P18, אנדרואיד 13) | session עם `USER_ACTION_NOT_REQUIRED` + ההרשאה `UPDATE_PACKAGES_WITHOUT_USER_ACTION` | **לא** — האפליקציה מעדכנת את עצמה, אחרי שפעם אחת אושר "התקנת אפליקציות לא מוכרות" (הגדרת אבטחה שהמשתמש מאשר) |
| אנדרואיד 10/11 (ה-F20, אנדרואיד 10) | `ACTION_INSTALL_PACKAGE` + FileProvider (session ל-UI של המתקין נכשל שם ב-"Parse error when parsing manifest") | **כן** — מסך האישור של אנדרואיד; אין דרך לדלג בלי device owner |

- **מה השתנה עכשיו בקוד** (`pos-android …/data/repo/AppUpdateRepository.kt`): עד היום אנדרואיד 10/11 הלך תמיד במסלול המסך, גם כשהקופה
  device owner, ודרש את ההרשאה "לא מוכרות" גם ל-device owner. עכשיו: **כשהאפליקציה device owner — תמיד session (שקט)**, בלי בדיקת
  ההרשאה; אם ב-F20 ה-session של ה-device owner בכל זאת נכשל, אותה גרסה עוברת בניסיון הבא למסלול המסך (לא נתקעים). שום הגדרת מכשיר לא שונתה.
- **device owner** — פעם אחת, ידנית, על מכשיר בלי חשבונות (או אחרי איפוס): `adb shell dpm set-device-owner il.co.runnersys.pos/.system.PosDeviceAdmin`
  (`docs/KIOSK.md` בקופה). נותן: התקנות ועדכונים שקטים בכל גרסה; נעילת קיוסק מלאה (lock task בלי "הצמדת אפליקציה" ובלי יציאה
  במחווה); אפליקציית בית קבועה; מסך דולק בטעינה; רשימת אפליקציות מותרות (Agamento, QuickSupport). הסרה — "הסרת הקופה כבעלת המכשיר"
  במסך הטכנאי.
- **MDM / Android Enterprise** (Esper, Hexnode, Scalefusion, Knox וכו׳) — אותו כוח בקנה מידה: רישום ב-QR באתחול, דחיפת APK בשקט
  (גם ללא ה-OTA שלנו), מדיניות עדכוני מערכת (חלון לילה), נעילת קיוסק, חסימת הגדרות. אז ה-MDM הוא ה-device owner, והאפליקציה שלנו
  מקבלת התקנות שקטות דרכו (או שה-MDM מאשר את ה-OTA שלנו). יצרנים (Sunmi, Kozen) מציעים לפעמים התקנה שקטה דרך ה-SDK שלהם — לא בשימוש.
- התנהגות האנדרואיד מול הענן לא השתנתה: הבקשה בלי `platform` = אנדרואיד; כל המפתחות הקודמים בתשובה נשארו.

## 6. בדיקות

- **ענן** (`server/tests/test_app_releases.py`): פלטפורמה, העלאת מתקין Windows, קדימות שיוכים לכל פלטפורמה, פריסה מדורגת, rollback
